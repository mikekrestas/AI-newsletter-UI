Stay signed in.

Signal can remember your Gmail connection across page refreshes, closed tabs and browser restarts. Google access refreshes on the server; your browser holds a secure session cookie.

  1. In Google Auth Platform → Clients → your existing Web application, add this exact Authorised redirect URI: https://signal-ai-newsletters.ai-newsletter-ui.workers.dev/api/auth/callback. Keep the existing JavaScript origins.
  2. In your local Signal repository, run npm run setup:session. When Wrangler asks, paste the client secret for that Google Web application. The script stores it as a Cloudflare secret and creates an encryption key. Never paste a secret into app Settings, chat or a Git file.
  3. Run npm run deploy, refresh this website and connect Gmail once. Future visits restore your account automatically.

Google Testing mode

Gmail offline grants in External / Testing normally expire after seven days. For a lasting personal connection, change Google Auth Platform → Audience → Publishing status to In production, then connect again to obtain a new grant. Personal, unverified apps may still show Google's unverified-app screen. Publishing the OAuth configuration does not make Signal multi-user; the server continues to allow only its configured owner.

Signing out

Disconnect removes this browser's server session and cookie. Your other devices remain connected. Google can still require reconnection if access is revoked, the grant expires, or you clear browser cookies. Sessions persist for up to a year of inactivity and are renewed during use; no app can guarantee that a Google grant lasts forever.

Privacy

Access and refresh tokens are encrypted in your existing private Cloudflare KV using a Worker secret. They are never returned to browser JavaScript or written to local storage. The cookie is Secure, HttpOnly and SameSite=Lax. This uses the existing free Worker and KV, without another paid service.
